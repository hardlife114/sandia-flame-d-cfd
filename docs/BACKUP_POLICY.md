# 备份规范 —— 每次大规模计算必须执行

> 用户要求（2026-09-20）：
> **"每次大规模计算都要备份，标准是根据备份的文件可以复现这次计算。"**
>
> 本文定义"可复现"的判定标准与固定操作流程。

---

## 1. 什么叫"可复现"

判断标准只有一条：**把备份交给我（或任何人），不需要额外口头信息，就能在本机重跑出同一结果。**

这要求备份必须覆盖以下**全部**要素（缺一不可）：

| # | 要素 | 为什么必需 | 载体 |
|---|---|---|---|
| 1 | **代码版本** | 脚本行为由 commit 唯一确定 | git commit hash |
| 2 | **网格** | 网格变了结果就变 | `.msh` 文件 **或** 生成命令+参数（可重建） |
| 3 | **算例定义** | 模型/边界/求解参数全在里面 | `case.h5`（含网格指针与全部设置） |
| 4 | **边界条件逐项值** | 用户硬规则：必须与算例定义一致 | 驱动日志的**回读记录**（不是回忆） |
| 5 | **阶段序列** | 只跑点火段 vs 跑完自持段，结果完全不同 | 冷流步数 / 反应步数 / 分段方式 |
| 6 | **环境** | Fluent 版本影响数值行为 | 版本号 + 并行核数 |
| 7 | **结果指标** | 用于复核重跑是否一致 | 逐站 RMS 等 |

> ⚠️ `data.h5`（收敛场）**不是**复现必需——它是结果，不是定义。
> 但它是**复核**的依据（判断重跑是否真的一致），所以一并备份。

---

## 2. 备份分三层

| 层 | 内容 | 存放 | 是否入 GitHub |
|---|---|---|---|
| **L1 归档清单** | `archive/<tag>/MANIFEST.md` + `manifest.json` | 项目内 | ✅ 入（很小） |
| **L2 算例文件** | `case.h5` + `data.h5` + `.msh` + 驱动日志 | 本机备份目录（另设磁盘优先） | ❌ 不入（单算例约 330 MB） |
| **L3 代码** | 全部脚本、文档、机理 | git 仓库 | ✅ 入 |

**为什么 L2 不入库**：单个算例 `case(22 MB) + data(147 MB) + mesh(160 MB) ≈ 330 MB`，
多次计算会迅速把仓库撑到数 GB。GitHub 适合放"定义与代码"，大文件放本地/外部盘。

## 3. 固定操作流程（每次大规模计算后）

```bash
# ① 生成归档清单 + 备份大文件（含 sha256 校验）
python scripts/archive_run.py --tag <算例名> --backup-dir D:\flamed_backup

# ② 归档器会做「复现充分性自检」，7 项必须全 ✓
#    若「工作区干净」为 ✗，说明改动未提交 → 执行 ③

# ③ 提交并推送到 GitHub，同时打版本标签
./sync.sh "算例 <算例名> 完成：<关键指标>" --tag v0.X.Y

# ④ 复核：从备份重跑一次（可选，重要结论建议做）
```

### 归档器的自检项

```
✓ 网格可重建或已备份
✓ 算例定义 case.h5 在位
✓ 边界条件有逐项回读记录
✓ 进口组分有实测记录
✓ 阶段序列已记录
✓ 代码版本已锁定
✓ 工作区干净（无未提交改动）
→ ✅ 满足「可复现」标准
```

**任何一项 ✗ 都视为本次备份不合格**，必须先补齐再进入下一次计算。

---

## 4. 什么算"大规模计算"，必须走本流程

- 任何 Fluent 求解迭代（哪怕只有 25 步的分段），只要**产出会被用于结论**
- 网格生成（结果 `.msh` 必须备份，因为重建涉及脚本版本）
- 长时间后处理/导出（产出新的对标数据）

**不算**：只读探测（`probe_*.py`）、纯后处理出图（读已有 CSV/PNG）、
不产出新结论的调试运行。

## 5. 版本编号约定

| 版本 | 含义 |
|---|---|
| `v0.1.0` | 初始：3D 圆进口 EDM 对标完成（242–264 K） |
| 次版本 `v0.X.0` | 换了模型 / 域 / 网格等**会改变结论**的改动 |
| 修订号 `v0.X.Y` | 修 bug、补分析、改文档等不改变已有结论的改动 |

打标签用 `./sync.sh "..." --tag vX.Y.Z`，标签会一并推送。

## 6. 恢复流程（拿到备份怎么复现）

```bash
# 1) 检出对应代码版本
git checkout <manifest 里记录的 commit>

# 2) 恢复大文件（若从备份盘恢复）
#    备份目录结构：D:\flamed_backup\<tag>\{*.msh, *.cas.h5, *.dat.h5, driver_*.log}
#    校验完整性：
sha256sum -c BACKUP_SHA256.txt     # 位于同一备份目录

# 3) 网格若未随备份携带，按 MANIFEST.md 里的生成命令重建

# 4) 读取算例定义并重跑
#    case.h5 内含网格与全部设置，可直接续算或从头跑；
#    重跑参数见 MANIFEST.md 的「求解设置与阶段序列」

# 5) 复核结果：与 MANIFEST.md 里的「对标结果」对比
```
